# Sidebar Pages Guide

This documents every page in the "Geophysicist Menu" sidebar of the frontend dashboard (`frontend/src/App.jsx` and its tab components) — what each one shows, what data it reads, and how it works under the hood. Pages are listed top-to-bottom in sidebar order.

Two things apply across nearly every page:
- **Data source**: pages either read from the pre-generated `frontend/src/data.js` (per-well logs + V11 predictions, built by `ml_training/generate_frontend_data.py`) or fetch large binary volumes directly from `frontend/public/*.bin` at runtime.
- **Rendering**: all seismic/property sections are drawn on plain HTML5 `<canvas>` elements (no charting library, no WebGL) — pixel-by-pixel color mapping done in JavaScript. `recharts` is used only for a handful of line/area charts (e.g. trend curves).

---

## 1. Executive Summary
**Tab key**: `overview`

Landing dashboard. A narrative summary of the well-seismic ML prediction workflow — cross-well calibration approach, regularized regression pipelines, out-of-fold (OOF) prediction philosophy. Mostly static descriptive text and headline stats; no heavy data loading.

## 2. Borehole Map & Section
**Tab key**: `map`

A spatial map of all 7 wells (Z-02, Z-03, Z-04, Z-05, Z-06, Z-07, Z-08-ST-02) positioned over the seismic survey's inline/crossline grid, plus a cross-section view. Well coordinates and inline/crossline mapping come from `well_seismic/output/auto_well_horizon_mapping.json` (generated by `well_seismic/auto_well_seismic_aligner.py`). Useful for orienting yourself before diving into well-specific tabs.

## 3. Pipeline Upgrades & Verification
**Tab key**: `workflow_story`

A narrative walkthrough of the V8 → V9 → V10 → V11 model evolution — what broke at each stage and how it was fixed (baseline shift, scale inflation, data leakage in blind-well selection, etc.). Illustrated with a step-by-step "lifecycle" image sequence.

> **Known gap**: the illustration images (`/lifecycle_images/1_seismic_section_wiggles.png` etc.) are referenced in code but no generator script for them exists anywhere in the repo — they were never included in this codebase. This section currently renders without its images.

## 4. Well-Seismic Tie Simulator
**Tab key**: `tie`

Interactive well-to-seismic tie QC tool. Select a well and view:
- **Tie QC Plot** — synthetic seismogram vs. real trace overlay, with correlation coefficient, best-fit wavelet frequency/phase, and bulk time shift
- **Impedance Inversion** — relative acoustic impedance inversion plot
- **Rock Physics Crossplot** — Lambda-Rho vs Mu-Rho colored by gamma ray

These are static PNGs generated by `well_seismic/impedance_tie.py` (tie/inversion plots) and `well_seismic/rock_physics.py` (rock physics crossplot), served from `frontend/public/well_images/{well}_{type}.png`. Not canvas-rendered — literal `<img>` tags with an `onError` fallback to Z-04's plot if a specific well's image is missing (e.g. Z-08-ST-02 has no rock-physics plot because the source script only processes wells named `Z-0N.las`, not the `-ST-02` sidetrack).

## 5. Spectral Decomposition
**Tab key**: `spectral`

Standalone CWT/SWT decomposition and denoising playground with a thin-bed tuning-thickness calculator (computes tuning thickness from a chosen velocity and dominant frequency, per the λ/4 rule). Runs entirely client-side against a well's log data from `data.js`.

## 6. ML Property Predictor
**Tab key**: `prediction`

An earlier/general-purpose ML predictor UI (predecessor to the flagship V11 Predictor near the bottom of the sidebar). Lets you compare predicted vs. actual logs for a selected well/property using the precomputed values baked into `data.js`.

## 7. Comparison spreadsheet
**Tab key**: `table`

Tabular actual-vs-predicted log comparison across wells and properties, sourced from `frontend/src/model_comparison_data.js`. Good for a quick numeric sanity check rather than visual inspection.

## 8. Grid Predictor Map
**Tab key**: `grid`

*Intended* to show 2D colored property maps (GR, DT, RHOB, VSH, PHIE, PHIT, SWE, a "Sweet Spot Index") across the full survey grid, using data from `frontend/src/grid_data.js`.

> **Currently non-functional.** `grid_data.js` is a stub (`export const gridData = null`) because the script that's supposed to generate it — `ml_training/generate_grid_predictions.py` — still targets a retired `ml_outputs_v8/` model file format (separate `*_scaler.joblib` / `*_selected_indices.joblib` files) that doesn't match how the current V11 models are actually saved (`*_model.joblib` + `*_feature_indices.joblib`, see `precompute_v11_slice_predictions.py` for the correct pattern). The page shows a static "Generating Grid Predictions…" placeholder with a spinner — **that spinner is not doing anything**, it's just an unconditional loading graphic; running the referenced script will fail immediately on a missing directory. Fixing this tab requires porting `generate_grid_predictions.py` to the V11 model format.

## 9. Geologist Gallery
**Tab key**: `gallery`

Image gallery of various generated plots from across the pipeline (well ties, inversions, rock physics, blind-well test plots) pulled from `frontend/public/well_images/` and `ml_outputs_v11/*.png`. A visual index rather than an interactive tool.

## 10. Thin-Bed Workbench
**Tab key**: `thinbed`

A guided, step-by-step (10-stage) walkthrough of the thin-bed resolution workflow: raw seismic → structurally-oriented filtering (SOF) → doublet/terrace attribute computation → 3D geobody segmentation and extraction (volume, bounding box, intersected wells). Backed by `frontend/src/thin_bed_data.js` (~1.8 MB), generated by `ml_training/compute_thin_bed_attributes.py`. This is one of the heavier compute scripts in the pipeline (~7-8 minutes to regenerate — it runs a full 3D gradient structure tensor, structurally-oriented filtering pass, and geobody segmentation over the whole volume).

## 11. CWT/SWT Study
**Tab key**: `cwt_swt`

Deeper wavelet-transform study tab — walks through the Continuous Wavelet Transform and Stockwell Transform decomposition track-by-track (raw trace → CWT envelope → SWT reassignment), explaining what each stage reveals. Educational/reference tab, computed client-side from well trace data.

## 12. SSWT Analyst
**Tab key**: `sswt_analyst`

Another wavelet-analysis-focused tab (`SswtTab.jsx`), similar in spirit to CWT/SWT Study but centered on the Synchrosqueezed Stockwell Transform specifically — its sharper frequency localization vs. CWT's smoother/more noise-robust output. Reads `wellsData` from `data.js`.

## 13. Cross-Correlation Study
**Tab key**: `xcorr`

A standalone deep-dive on the well-tie cross-correlation methodology (separate from the interactive Tie Simulator in position 4) — explains the grid-search over wavelet frequency, phase, and bulk time shift used to maximize correlation between synthetic and real traces.

## 14. 3D Reservoir Viewer
**Tab key**: `volume3d`

*Intended* to render a rotatable 3D solid-block model of a chosen property (Sweet Spot Index, Effective Porosity, Lambda-Rho, Shale Volume, Water Saturation) with camera yaw/pitch sliders and depth slicing controls.

> **Currently non-functional** for the same reason as Grid Predictor Map — it also depends on `grid_data.js`, which is a null stub. The 3D block canvas renders black/empty until that data pipeline is fixed.

## 15. Geological R² Scorecard
**Tab key**: `r2_scorecard`

A plain-language scorecard explaining the geological significance of each target property's blind-well R² score (LMRHO as the fluid/gas indicator, VSH for shale volume, PHIE for porosity, GR, SWE for water saturation) — written for a non-ML audience (e.g. "why does this number matter for finding sweet spots").

> **Known data-accuracy issue**: the specific R² numbers shown here (e.g. LMRHO +0.50, VSH +0.062) are hardcoded in the component and do **not** match the actual blind-well results from the currently-trained V11 model (which shows LMRHO at roughly −0.27, VSH at roughly −0.21 in `ml_outputs_v11/model_performance.csv`). The numbers look like they were baked in from an earlier/different training run rather than read live from `model_performance.csv`. Treat this tab's numbers as illustrative, not authoritative — check `ml_outputs_v11/model_performance.csv` directly for the real current results.

## 16. Spectral Whitening
**Tab key**: `spectral_whitening`

A before/after spectral whitening comparison per well — shows a Geoteric-style workflow (Ormsby bandpass 8-70 Hz, trace-by-trace AGC, amplitude masking) with SNR and dominant-frequency stats (e.g. "SNR 17.9x").

> **Known gap**: this tab is `<img>`-based, not canvas-based, pointing at `/seismic_images/spectral_{well}.png`. No script anywhere in the repo generates these files, and no `seismic_images/` directory exists on disk — the images were never included in this codebase. This tab currently shows blank image placeholders.

## 17. Thin Bed Frequency
**Tab key**: `thin_bed_frequency`

A focused view on frequency-domain thin-bed detection (tuning thickness vs. frequency relationships). Works correctly; renders on canvas from client-side computation over well data.

## 18. Spectral Explorer
**Tab key**: `spectral_explorer`

Side-by-side raw-vs-enhanced seismic section viewer. Toggle between four enhancement methods — CWT envelopes, SSWT reassignment, spectral whitening, dominant-frequency shift — with power-spectrum and SSWT heatmap insets. Computes client-side using `sswt_helper.js` against `seismic_raw.bin`.

## 19. ML SSWT Kink Explorer
**Tab key**: `ml_kink_explorer`

2D section explorer for the SSWT "kinks" concept: sharp 2nd-derivative inflection points in the acoustic-impedance curve that mark exact thin-bed top/base boundaries. Two side-by-side panels — raw seismic (Panel A) vs. an ML-style reconstructed profile with distinct white horizon lines and optional dashed-gold kink overlay (Panel B). Everything is computed **entirely in-browser** in JavaScript (`computeSSWTMLSection()` in `MlKinkExplorerTab.jsx`) from the raw seismic trace data fetched from `seismic_raw.bin` — this is a from-scratch reimplementation of the SSWT ridge-tracking logic in JS, not a call to any trained model.

> This tab had a real React state-batching bug where Panel B never rendered (the redraw-trigger state could get collapsed by React 18's automatic batching before the browser ever committed an intermediate render). Fixed by adding a monotonically-increasing version counter as the redraw trigger — see commit `bbc5b5d`.

## 20. V11 ML 3D Seismic Predictor (badge: NEW)
**Tab key**: `ml_v11_predictor`

The flagship tab. Runs the actual trained V11 model pipeline against the full 3D seismic volume. Select a well location (including the two genuinely blind test wells, Z-04 and Z-08-ST-02) and a target property (VSH, SWE, PHIE, PHIT, GR, RHOB, DT, AI), and it shows:
- **Panel A** — raw seismic profile through that well's inline
- **Panel B** — the V11 model's predicted property profile for the same section

Data comes from the precomputed 3D prediction volumes in `frontend/public/v11_pred_{property}.bin` (one ~37 MB Int16 volume per property, generated by `ml_training/precompute_v11_slice_predictions.py`) plus `seismic_raw.bin` for Panel A. These are real model outputs — genuinely the most representative tab for "what did the V11 pipeline actually predict."

## 21. HD Well Seismic Zoom (badge: ZOOM)
**Tab key**: `ml_well_zoom`

A high-resolution, zoomable borehole-centered seismic viewer. Three zoom levels (±14, ±50, ±125 crosslines around a well) let you inspect the seismic response immediately around a borehole in much finer detail than the full-section views elsewhere. Reads the same `v11_pred_*.bin` and `seismic_raw.bin` volumes as the V11 Predictor tab, just windowed tightly around the selected well's coordinates.

## 22. SSWT ML Methodology & Story (badge: STORY)
**Tab key**: `sswt_journey`

A guided, presentation-style narrative tab walking through the entire SSWT-ML kink-detection methodology end to end — intended as the "explain this to a reviewer" tab, including a blind-well validation figure and a feature-correlation-matrix figure.

> **Known gap**: both key figures (`/blind_wells_validation.png`, `/feature_correlation_matrix.png`) come from the **separate** `sswt_ml_kinks_workflow/` sub-pipeline (a distinct 6-script pipeline — `1_extract_sswt_features.py` through `6_feature_correlation_analysis.py`, plus `generate_perfect_verification_plot.py`) that trains its own standalone AI-regression and kink-classification XGBoost models. This sub-pipeline has **not** been run in this environment, so this tab's images are currently missing. Running it end-to-end would populate them; ask if you want this done.
